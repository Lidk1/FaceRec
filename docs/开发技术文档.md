## 1. 项目概述

### 1.1 建设目标

校园食堂、超市长期依赖实体校园卡，存在易丢失、补卡繁琐、充值排队等痛点。本子系统是校园人脸支付
平台的身份核验底座，用自研训练的 FaceNet2Rec 模型完成"人脸注册 → 特征加密入库 → 实时刷脸核验"，
向后续账户与交易模块输出**可信的用户身份**（`user_id` + 相似度 + 耗时），不涉及资金操作。

对应需求：FR-01 用户注册与人脸录入、FR-02 人脸采集与特征提取、FR-04 动态刷脸支付中的身份核验、
FR-09 人脸特征库管理、FR-12 模型效果监测，以及 CSCI-FUN-01/02、SYS-02、SYS-07 隐私约束。

### 1.2 功能边界

| 已实现（本子系统） | 不在本子系统 |
| --- | --- |
| 人脸检测、主人脸选取、512 维特征提取 | 模拟资金账户、充值、扣费（支付子系统） |
| 特征向量 AES-256-GCM 加密入库、特征库管理 | 交易幂等、离线缓存同步（支付子系统） |
| 1:N 刷脸核验、1:1 比对、阈值判定 | 管理员 RBAC 登录（运维子系统） |
| 识别记录与成功率/失败分布统计 | 流水审计、对账报表 |
| Web 终端（摄像头/上传）、注册与特征库页面 | 真实支付清算 |

### 1.3 技术选型与理由

| 层次 | 选型 | 理由 |
| --- | --- | --- |
| Web 框架 | Flask 2.3.3 | 轻量、蓝图分层清晰，课程规模无需 Spring 级框架 |
| 推理后端 | OpenCV DNN（CPU） | 直接加载 FaceNet 冻结图，免装 TensorFlow/PyTorch，产物体积与部署成本低；单帧约 40ms 满足 ≤2000ms 指标 |
| 检测 | Haar 级联 alt2 + default | OpenCV 内置、零额外权重、CPU 20~60ms；检测器已接口化，可平滑替换 MTCNN |
| 存储 | SQLite（演示）/ MySQL 8.0（正式） | 演示零配置；正式库沿用《类图与数据库设计说明书》表结构 |
| 加密 | AES-256-GCM | 认证加密，密文自带完整性校验，防止特征被篡改或重放 |
| 前端 | 原生 HTML/CSS/JS | 无 Node 构建链，`getUserMedia` 直接调摄像头，降低演示环境要求 |

### 2.3 模型准备（关键步骤）

发布的 `20180402-114759.pb` 是**训练期计算图**：包含 `batch_join/fifo_queue` 队列，
批归一化用 `tf.cond(phase_train, ...)` 生成训练/推理两条分支（2019 个 Switch、449 个 Merge），
训练分支里还有 `random_uniform`。OpenCV DNN 导入时会实例化图中全部节点，因此**原始图无法直接加载**。

项目自带裁剪工具，在字节级解析 GraphDef 完成三件事：

1. 以 `phase_train = False` 折叠 cond 分支（死分支剪除）；
2. 删除队列节点，并把 `input` 节点重建为真正的 `Placeholder`（NHWC `[-1,160,160,3]`）；
3. 只保留输出 `InceptionResnetV1/Bottleneck/BatchNorm/Reshape_1`（BN 后的 512 维向量，L2 归一化在应用层完成）依赖到的节点。

```powershell
# 原始图放到 model/20180402-114759.pb 后执行
python scripts/prune_graph.py model/20180402-114759.pb model/facenet2rec-inference.pb
```

输出样例：

```
source : model\20180402-114759.pb  (91.3 MB, 5903 nodes)
output : model\facenet2rec-inference.pb  (90.0 MB, 1623 nodes)
折叠: Switch=2019 Merge=449 死节点=2030
算子分布: Const=653, Identity=491, Conv2D=132, Relu=131, FusedBatchNorm=112, ConcatV2=23, Mul=22, BiasAdd=21
```

裁剪后模型规格：

| 项 | 取值 |
| --- | --- |
| 输入 | `input`，float32，NHWC `[N,160,160,3]`，RGB，按 `(x-127.5)/128` 标准化 |
| 输出 | `InceptionResnetV1/Bottleneck/BatchNorm/Reshape_1`，`[N,512]` |
| 参数量/文件 | 约 23M 参数 / 90MB |
| 推理耗时 | CPU 约 35~60ms/帧（i5 级 4 核） |

模型文件不纳入 Git（见 `.gitignore`），随可执行产物一起分发。

## 4. 核心逻辑

### 4.1 人脸注册流程

```
浏览器采集 1~5 帧
      │  (Base64 dataURL / multipart)
      ▼
POST /api/face/enroll ──► 参数校验（学号格式、姓名、帧数）
      │
      ▼
FaceEngine.extract_many
      ├─ 每帧：Haar 检测 → 人脸数判定
      │     0 张 → 记录失败原因（1001）
      │     >1 张 → 记录失败原因（1002）
      │     1 张 → 裁剪(扩边 18%) → 160×160 → FaceNet 推理 → L2 归一化 → 质量评分
      ▼
至少 1 帧有效，且最高质量 ≥ 0.10
      │
      ▼
AesFeatureCipher.encrypt(向量)  →  v1:k1:<base64(nonce‖ciphertext‖tag)>
      │
      ▼
FaceStore：INSERT fr_user + fr_feature（失败删除用户，避免"有用户无特征"）
```

校验规则：

| 字段 | 规则 | 失败错误码 |
| --- | --- | --- |
| 学号/工号 | 2~20 位字母、数字、`_`、`-`，全局唯一 | 400 / 1006 |
| 姓名 | 非空，≤20 字符 | 400 |
| 图像 | 1~10 帧（入库上限 5），单帧 ≤8MB | 400 / 413 |
| 人脸 | 每帧仅允许 1 张，质量分 ≥0.10 | 1001/1002/1003 |
| 覆盖 | `replace=true` 时保留用户资料、替换样本 | — |

质量分公式（0~1）：`0.55×清晰度(Laplacian 方差/120) + 0.25×尺寸((边长-60)/140) + 0.20×画面占比`。

### 4.2 刷脸核验流程

```
POST /api/face/recognize（1 帧）
   │
   ├─ 特征库解密：SELECT 全部有效密文 → AES-GCM 解密 → 512 维向量
   ├─ 检测：0 张 → result_type=2（无人脸）
   │        >1 张 → result_type=3（多人，拒绝）
   │        1 张 → 取主人脸 → 编码 → 遍历特征库计算余弦相似度 → 取最高
   ├─ 判定：sim ≥ 0.70 → 1（成功，返回用户）；否则 4（相似度不足）
   ├─ 超时：cost_ms > 2000 → 5（超时，前端引导刷卡降级）
   └─ 落库：写 rec_recognize_log（结果、相似度、阈值、人脸数、耗时、终端）
```

结果类型（与数据库 `result_type` 一致）：

| 值 | 含义 | 前端处理 |
| --- | --- | --- |
| 1 | 识别成功 | 展示姓名/学号/相似度，进入支付流程 |
| 2 | 未检测到人脸 | 提示正对镜头 |
| 3 | 检测到多张人脸 | 提示仅保留一人 |
| 4 | 相似度不足 | 提示重试或降级刷卡 |
| 5 | 识别超时（>2000ms） | 提示降级刷卡 |
| 6 | 识别异常（模型/图像异常） | 提示稍后重试 |

### 4.3 检测与主人脸选取

- 画面宽于 800px 时先等比缩放，检测框再映射回原图裁剪，兼顾速度与画质；
- alt2 主检测器无结果时用 default 兜底；
- 同尺度重叠框按 IoU>0.4 去重（保留大面积框）；
- 主人脸规则：面积 ≥ 最大脸 70% 的候选集中，取 `面积比 − 0.6×中心距` 最大者，
  即"面积相近时取画面中心"，对应 SRS FR-04。

### 4.4 特征提取预处理

1. 以检测框为中心外扩 18%，边界裁剪到图像内；
2. `cv2.resize` 到 160×160（双线性）；
3. `blobFromImage(scale=1/128, mean=(127.5,127.5,127.5), swapRB=True)`，等价 FaceNet 的
   `fixed_image_standardization` 与 RGB 输入约定；
4. OpenCV DNN 前向推理（互斥锁保护，Net 非线程安全）；
5. 输出 512 维向量做 L2 归一化，落库前再验维度。

### 4.5 特征加密与密钥管理

密文格式：`v1:<key_id>:<Base64(nonce(12B) ‖ ciphertext ‖ tag)>`

- AES-256-GCM，每次加密随机 nonce，同一向量两次加密结果不同；
- AAD 绑定 `版本|key_id|维度|float32`，跨版本/跨维度重放会校验失败；
- 解密校验失败（密钥错误、密文篡改）抛 `CipherError`，服务层跳过该条特征并继续识别；
- 密钥支持版本号（`v1:k1`），换钥时新数据写新 key_id，旧数据保留可读；
- 任何接口、日志、导出都不返回密文或明文向量，用户详情只给维度/质量/模型版本。

### 4.6 相似度阈值校准

在 6 位演示用户、17 条特征上实测（注册样本与探测照片不同）：

| 场景 | 最高余弦相似度 |
| --- | --- |
| 同人（未参与注册的照片，3 组） | 0.783 / 0.887 / 0.943 |
| 异人（不同用户间最高，15 对） | ≤ 0.572 |
| 陌生人（未注册） | 0.006 |

设计基线为 0.75，但实测同人最低 0.783、异人最高 0.572，取 **0.70** 可同时留出
约 0.08 的拒识余量和 0.13 的误识余量。阈值可通过 `FACE_THRESHOLD` 环境变量或
`sys_config.face.similarity.threshold` 调整，修改后无需重启（服务每次读取配置对象）。

### 4.7 并发与资源

- Flask `threaded=True`，每个请求独立数据库连接（SQLite WAL 模式）；
- 写操作（注册/删除）加进程内 `RLock`，避免 SQLite 写锁竞争；
- OpenCV DNN `Net` 与 Haar 级联均为共享对象，推理加锁串行，单进程吞吐约 15~20 帧/秒；
- 模型 90MB 常驻内存，进程峰值约 450MB（含 OpenCV/numpy）。

## 5. 类与模块说明

| 类 / 模块 | 职责 | 关键方法 |
| --- | --- | --- |

`FeatureCipher.encrypt/decrypt`。测试中通过注入 `FakeDetector`/`FakeEncoder`
即可在无模型环境下覆盖全部分支。

## 6. 接口说明

### 6.1 通用约定

- 协议：HTTP/1.1，UTF-8，JSON；上传也支持 `multipart/form-data`；
- 响应：`{"code": 200, "msg": "success", "data": {...}}`；
- 图像：`image`（单帧）或 `images`（多帧），值为 `data:image/jpeg;base64,...` 或纯 Base64；
- 业务错误 `code≥1000`，HTTP 状态码按语义返回 400/404/409/413/500。

错误码：

| code | HTTP | 含义 |
| --- | --- | --- |
| 200 | 200 | 成功 |
| 400 | 400 | 参数校验失败（含学号、姓名、图像格式） |
| 413 | 413 | 上传内容超过 8MB |
| 404 | 404 | 用户/接口不存在（1007 为用户不存在） |
| 405 | 405 | 方法不支持 |
| 409 | 409 | 学号已注册（1006） |
| 500 | 500 | 系统内部异常 |
| 1001 | 200 | 未检测到人脸 |
| 1002 | 200 | 检测到多张人脸 |
| 1003 | 200 | 人脸质量过低 |
| 1004 | 503 | 模型未就绪 |
| 1005 | 200 | 识别超时 |
| 1007 | 404 | 用户不存在 |
| 1008 | 404 | 无有效特征 |
| 1009 | 503 | 存储不可用 |

`POST /api/face/recognize`

```json

```

失败示例（相似度不足）：

```json
{"code":200,"msg":"最高相似度 0.412 低于阈值 0.70",
 "data":{"passed":false,"result_type":4,"result_text":"相似度不足","similarity":0.412,...}}
```

> 识别失败仍返回 HTTP 200（`code=200`），业务结果由 `result_type/passed` 表达，
> 便于终端连续取帧；仅参数/权限/系统错误使用 4xx/5xx。

## 7. 数据库设计

### 7.1 概念模型

```
FR_USER 1 ──< FR_FEATURE        （一个用户 1~5 条有效特征）
FR_USER 1 ──< FR_RECOGNIZE_LOG  （一个用户多条识别记录，失败记录 user_id 为空）
FR_CONFIG                        （阈值、超时等运行参数）
```

正式库沿用《类图与数据库设计说明书》：`sys_user`、`face_feature`、`rec_recognize_log`、
`dev_terminal`、`mch_merchant`、`sys_config`，字段名与约束见 `sql/mysql/01_schema.sql`。

### 7.2 演示库（SQLite，随程序自动创建）

| 表 | 关键字段 | 约束/索引 |
| --- | --- | --- |
| `fr_user` | user_id, user_no, user_name, dept, phone, status | `user_no` 唯一；`idx_user_no` |
| `fr_feature` | feature_id, user_id, feature_no, feature_cipher, feature_dim, model_version, quality_score | `(user_id,feature_no)` 唯一；级联删除；只存密文 |
| `fr_recognize_log` | record_id, user_id, result_type, similarity, threshold, face_count, cost_ms, recognize_time | `idx_recog_time`、`idx_recog_result` |
| `fr_config` | config_key, config_value, value_type | 主键 key |

### 7.3 隐私与完整性

- 库中不存在原始人脸图像字段，程序也不写图片文件（上传图像仅在内存中处理）；
- `feature_cipher` 为密文，AAD 防篡改；删除用户级联删除特征；
- `sim`、`threshold` 用 REAL/DECIMAL 保存，便于模型效果回溯；
- 正式库金额/时间字段沿用设计：`DECIMAL(12,2)`、`DATETIME(3)`、utf8mb4。

## 9. 性能与安全

### 9.1 实测性能（i5-1240P，CPU 推理，6 用户/17 特征）

| 阶段 | 耗时 |
| --- | --- |
| 模型加载（冷启动） | 约 1.5s |
| 检测（640px 帧） | 15~35ms |
| 特征推理（160×160） | 35~55ms |
| 特征库解密+比对（17 条） | <5ms |
| 单次识别接口（预热后） | 48~85ms |

满足 SRS"单帧推理 ≤2000ms、响应 ≤3s"的指标；超时判定仍保留在引擎层。

### 9.2 安全措施

| 风险 | 措施 |
| --- | --- |
| 人脸隐私泄露 | 不存原图；特征 AES-256-GCM 加密；接口不返回密文 |
| 密文篡改/重放 | GCM 认证标签 + AAD 绑定版本与维度 |
| 越权删除 | 删除接口校验用户存在性；生产部署前置于 RBAC 网关 |
| 路径注入 | 仅接受 Base64/上传流，不落盘、不拼接文件路径 |
| 中文路径 | 模型走内存加载、图片走 `imdecode`、级联复制到 ASCII 临时目录 |
| 异常信息泄露 | 统一异常处理，前端只见中文提示与业务错误码，堆栈仅入日志 |
| 暴力重试 | 前端连续识别间隔 1.2s；服务端单进程串行推理 |

### 9.3 日志

`logs/facerec.log`（5MB 轮转，保留 3 份）记录启动配置、业务异常（含错误码）、
未捕获异常堆栈；不记录图像内容、特征明文与密钥。

## 11. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动显示"模型未就绪" | 未放 `facenet2rec-inference.pb`，或仍是未裁剪的训练图 | 按 2.3 执行裁剪脚本，确认 `/api/face/status` 的 `ready=true` |
| 摄像头无法打开 | 非 localhost/HTTPS、浏览器未授权、设备被占用 | 用 `http://127.0.0.1:8080` 访问并允许权限 |
| 识别总判"未检测到人脸" | 光线过暗、人脸过小（<80px）、侧脸 | 靠近镜头、补光；可调小 `FACE_MIN_SIZE` |
| 中文路径下检测器不可用 | OpenCV 窄字符接口 | 已内置临时目录复制；若仍失败，将程序放到纯英文路径 |
| 端口被占用 | 8080 已被其它服务使用 | `python run.py --port 8090` |
| 中文控制台乱码 | Windows 控制台代码页 | `chcp 65001` 或设置 `PYTHONIOENCODING=utf-8` |
| 注册提示"多张人脸" | 画面有照片/海报人脸或背景人像 | 换单人画面；或删除误检样本后重试 |
